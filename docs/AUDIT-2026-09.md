# Audit workflow — settembre 2026

Perché i giochi uscivano "a cubi, prop sottoterra, piatti", cosa esiste online, cosa è stato cambiato.

## 1. Cause radice (trovate nel repo)

| Sintomo | Causa | Fix |
|---|---|---|
| Prop 10 cm sottoterra | `unity-loop.md` diceva "ground cube at y=0" (centro a 0 → faccia sopra a +0.1/+0.5); `greybox.md` diceva il contrario. Nessuna verifica numerica: "il parent legge il PNG". | Ground top = Y 0 ovunque; `GDS.SceneLint` raycast + bounds → `issues: 0` è il gate. |
| Strutture grandi = cubi Unity | 1 pezzo kit per worker, max 3 per chat, hard stop: una casa (40 moduli) = 14 chat → nessuno arrivava in fondo. `manage_probuilder` face-by-face (indici instabili) → l'agente mollava e lasciava il cubo. | Blueprint JSON → `GDS.LevelBuilder` (kit) / `GDS.PB` (ProBuilder da C#): 1 edificio = 1 chiamata. |
| Estetica piatta | Nessuna fase luci / post-processing / skybox / VFX / shader. CoplayDev ha `manage_graphics`, `manage_vfx`, `execute_code`: mai usati. | Fase `lookdev` (`GDS.LookDev.Apply(preset)`), `GDS.VFX`, toon/outline opzionali. |
| Niente personaggi / nemici | Non in pipeline; skill `initialize-ai-navigation` installato ma mai richiamato. | Fase `characters` (`GDS.Characters` + KayKit/Kenney/Quaternius UAL) + NavMesh. |
| Divieti controproducenti | HDRI vietato (skybox è standard), Sketchfab vietato (token gratis), gen3d vietato in blocco. | HDRI ok come skybox; Sketchfab CC0 ok; gen3d = tier scelto in intervista con budget. |

## 4. Note operative

- Unity 6000.5.3f1 (installata) è tech stream: ProBuilder 6.0.x **non compila** lì; l'installer fissa 6.1.2. Per stabilità: 6000.3 LTS.
- `execute_code` (gruppo `scripting_ext`) va abilitato nel MCP for Unity: è il ponte verso `GDS.*`.
- Il lint non copre compenetrazioni prop-prop né NavMesh: i worker le vedono in Play Mode.
- Il builder allinea per bounds; kit con pezzi "aperti" (muri con spessore 0) funzionano ma i vani porta seguono il pezzo `wallDoor` del kit, non la misura Geometra.

## 5. Terza iterazione (25 set 2026): CLI, stili, mondi, art review

**Ricerca**
- Unity ha pubblicato il 9/9/2026 il [plugin ufficiale per Claude Code](https://unity.com/blog/unity-plugin-for-claude-code) (29 skill + Unity CLI). La [Unity CLI](https://unity.com/blog/meet-the-unity-cli) + il pacchetto `com.unity.pipeline` pilotano l'Editor aperto in 200-600 ms senza ricompilare: `unity command eval`, 162 comandi built-in (scene, test, play, screenshot, package, bake) e comandi custom con `[CliCommand]` ([guida eval](https://perflint.dev/blog/unity-cli-eval-mcp-guide/), [limiti attuali](https://vindler.solutions/blog/unity-cli-agent-automation)). [unity-agent](https://github.com/m4bwav/unity-agent) consiglia CLI prima e MCP come fallback per costo in token degli schemi.
- Unreal 5.8 (giugno 2026) ha un [MCP server first-party](https://dev.epicgames.com/documentation/unreal-engine/unreal-mcp-in-unreal-editor) (Unreal MCP + All Toolsets, `http://127.0.0.1:8000/mcp`, tool-search `list_toolsets`/`describe_toolset`/`call_tool`) e il [plugin Epic per Claude Code](https://github.com/EpicGames/unreal-engine-skills-for-claude-code-plugin). Megascans gratis per UE → il realistico va su Unreal.
- Workflow altrui: [Claude-Code-Game-Studios](https://github.com/Donchitos/Claude-Code-Game-Studios) (49 agenti, gerarchia da studio, niente pipeline estetica), studi multi-agente con "art director" che fissa uno screenshot concept prima degli asset. Da qui la fase art-review con board di riferimento e punteggio.
- Distribuzione skill: [`npx skills`](https://github.com/vercel-labs/skills) usa `.agents/skills` come cartella canonica + link negli host → stesso schema adottato dall'installer.

- `GDS.Shots` (screenshot da render reale, anche headless), preset LookDev `toon-bright` / `realistic-overcast` / `realistic-golden`, skybox `GDS/SkyGradient`, nebbia scalata sulla dimensione del mondo.

- Installer: rilevamento host/tool/skill, installazione canonica + junction, merge del config.
