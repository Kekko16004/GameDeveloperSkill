# Nucleon bridge, less common commands and the raw MCP tool list

Core commands: [bridge.md](bridge.md).

| Command | Does | Gate evidence |
|---|---|---|
| `camera list\|add\|pilot\|stop\|shot` | Camera entities: `camera add Hero --pos 0,-20,6 --target 0,0,2 --focal 35 --dof --fstop 2.8 --focus 20`; `camera shot Hero out.png` pilots it, captures, stops piloting | PNG + lens |
| `post list\|add\|set` · `material domain PATH` | Post Process Volumes (`post add Night --unbound --set bloom=true --blendable Content/Materials/PP_Outline.ncmat:0.8`) and the Material Domain of a `.ncmat` (`--domain postProcess --post-location afterTonemap`) | the entity / the domain |
| `weather get\|set\|clear\|strike` | the `weather` tool (docs/rendering/WEATHER.md): `weather set --preset Rain --time 18.5 --wind-heading 90 --wind-speed 8 --param puddles=1` writes the level's World Settings (default scope; the level is dirty until `save`), `--scope project` Project Settings (saved at once), `--scope live --blend 30` only the running game (Play). Presets Clear Cloudy Overcast Rain Storm Snow Fog; `get` is short (level table, project keys, live preset / progress / time of day / wind heading), `--full` adds the blended values. Off until a preset is set (a level without a `weather` table looks as before) | the answer; screenshot to judge the look |
| `destruction ACTION` | the `destruction` tool (docs/engine/PHYSICS.md "Destruction", "Soft bodies and cloth"). No Play: `fracture --model M --pieces 24 --seed 3 [--clusters N --irregularity 0.35]` (writes `M.fracture`), `info --file F`, `make-actor --model M --path Content/Actors/Crate.ncactor --health 40 [--dynamic --staged --lifetime 12]` (actor = Mesh + Destructible, then `entity add actor '{"name":"Crate","asset":"Content/Actors/Crate.ncactor","position":[3,3,0.5]}'`), `make-cloth-actor --path P --shape grid --width 2 --height 1.2 --pin left --wind true`. In Play: `state`, `damage --entity Crate --amount 25`, `break`, `set-health`, `ray --from x,y,z --to x,y,z --amount 20 --impulse 4`, `explode --position x,y,z --radius-m 6 --force 500 --amount 80`, `cloth-wind --cloth 1 --wind 6,0,0` (Z up, not undoable) | `state` JSON: health, `broken`, pieces, `debris`, cloths |
| `memory [memory\|load\|text] [--kind cpu\|gpu]` | memory_stats: CPU/GPU memory by tag, video memory budget and usage, load timeline | JSON |

Raw MCP: every tool has a command above, `call <tool> '<json>'` reaches any other (52 tools at `a58cb429`, 49 in the frozen build; `ncli tools [NAME]` prints the schema of one; the 27 first: `editor_state`, `scene_list`, `scene_select`, `entity_get/modify/add/remove`, `asset_search`, `asset_import`, `list_commands`, `run_command`, `get/set_input_mapping`, `list/switch/open/close_document`, `play_control`, `read_log`, `viewport_camera`, `capture_viewport`, `camera_pilot`, `run_lua`, `profile_capture`, `material_domain`, `migrate_project`, `save_scene`). Every edit is undoable (`command edit.undo`); nothing is on disk before `save`. Added by the engine on 29 October (all reached with `call`, schemas in `docs/editor/MCP.md`; only `play_test` and `web_ui status` were tried by the skill, treat the rest as unverified and check the result): `landscape` (create, heightmap, sculpt / paint strokes, rules by slope and height, layers, splines) and `foliage` (types, paint, scatter by rules): a world no longer needs a Lua tool script for the terrain; `lighting_get` / `lighting_set` (the level's `lighting` table, applied live); `levels` (sublevels, streaming volumes); `open_level`; `asset_read` / `asset_write` (text of levels, actors, materials, Lua, `project.ncproject`); `input_bindings` (one binding at a time); `build` (package, cook, navmesh, reflection captures, GI, HLOD, optimize_level as jobs: `start` then `status`); `play_test` (inline `steps` or an `nc.test` script, docs/editor/PLAYTEST.md; tried: wait + Lua assert PASS); `web_ui` (NUI page: `status`, `nui_open`, `nui_send`, `nui_focus`, `nui_eval`); `natives_search` (signature + example of a native: use it instead of guessing); `gameplay_assets` / `gameplay_state` (abilities, effects, AI data; live state of the match, attributes, AI in Play); `animation_state`, `sequence`, `blueprint_graph` / `material_graph` / `anim_graph` / `fx_asset` (structured edits), `save_games`. Added later the same day (q1 `a58cb429`, tried: see the table rows): `weather`, `destruction`, `memory_stats`. Still not covered: project settings values, import settings, Game View.

**Snapshot gotcha.** `api-refresh --from-editor` dumps the registry by running the editor on `-run-lua` with a project as working folder, and the project's own `nc/` folder (the runtime Lua modules the editor copies in when it opens the project) comes BEFORE the editor's embedded modules: a project last opened by an older editor gives the OLD registry (404 natives instead of 694 on 2026-10-29) and no error. Give `--project` a project the current editor has opened (a fresh `exe new-project` folder has no runtime modules in `nc/` yet: run any `--stdio` command on it, e.g. `ping`, first); ncli now refuses a project with no `nc/natives.lua` and warns when it is older than the editor. Compare the `engine` revision and the count in the answer, and run `--dry-run` first: `added` must list the natives you expect. Without `--from-editor` it reads the checkout's committed `docs/api/lua/natives.json` (694 at `a58cb429`, equal to the built registry then), which can lag behind the sources.
