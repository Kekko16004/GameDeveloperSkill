# Nucleon gameplay, systems that exist only when the GDD asks for them (level streaming, weather, destruction and cloth, animation extras)

- **Level streaming** (engine docs `docs/engine/WORLD.md` "Level streaming", written but never run by the engine team): a persistent `.nclevel` lists `sublevels` (name, source, transform, `streaming = always|blueprint|volume`, ...) and `levelstreamingvolume` entities; runtime `nc.levels`; natives `LoadStreamLevel` and friends. There is no MCP tool for sublevels: author the `.nclevel` with the editor closed, or `command add.level_streaming_volume`; `command tools.optimize_level_for_streaming` / `exe optimize-level` turns a big flat level into instance groups + cells. Treat it as experimental and check it in Play.
- **Weather, time of day, wind, lightning** (engine docs `docs/rendering/WEATHER.md`, `nc.weather`, built 29 October; the MCP tool and `Weather.get()` answered in Play here, the picture was not looked at): one system for the cloud layer, rain / snow, wet and snowy surfaces, fog, the ONE global wind (vegetation, cloth, water) and the clock; it is OFF until a preset is set, so a level without a `weather` table is unchanged. Author it in the editor with `ncli weather set --preset Rain --time 18.5 ...` (level = World Settings, `--scope project` = every level of the game) and `save`; script it with the natives `SetWeather("Storm", 30)` (blend seconds), `SetTimeOfDay(19.5)`, `SetDayLength(minutes)` (0 stops the clock), `SetLatitude`, `SetWind(vec3(1,0,0), 12)`, `SetWeatherParam`, `TriggerLightning`, `SetThunderSound`, `SetPrecipitationScale`, `SetWeatherEnabled` and the readers `GetWeather`, `GetWeatherBlend`, `GetTimeOfDay`, `IsRaining`, `IsSnowing`, `GetWindDirection`, `GetWindSpeed` (the wind direction is a ground vec3, x east, y north). A material opts out of wet / snow with `weather = false` in the `.ncmat` (a screen, a car paint). Cost grows with the quality preset (drops 0.35x at Low .. 1.25x at Cinematic); `NC_WEATHER=0` turns the whole thing off. Mood work: pair a preset with the lookdev sun/sky of the level, then shoot it at the owner's GPU (software rendering washes the look out).
- **Destruction and cloth** (engine docs `docs/engine/PHYSICS.md` "Destruction" and "Soft bodies and cloth", `nc.destruction`, `nc.softbody`, built 29 October; tried here through the MCP tool: fracture of a 1 m crate into 12 pieces, actor with a Destructible placed in a level, `damage` 40 -> 25 health, `ray` 10 damage, `break` -> 12 debris, a grid cloth actor with the world wind): cut a model ahead of time (`ncli destruction fracture --model M --pieces 24`), make an actor from it (`make-actor`; its Mesh component must show the same model at the actor origin; do NOT add a Collision component, the Destructible makes the body), place it with `entity add actor`. In scripts: `CreateDestructible`, `DamageDestructible(d, amount, point, direction, impulse)` (true when this blow broke it), `FractureModel(model, options)`, `BreakDestructible`, `IsDestructibleBroken`, `GetDestructibleHealth`, `ApplyRayDamage(from, to, damage, impulse, ignore)` (a bullet: returns the `Raycast` hit plus the destructible), `Explosion(position, radius, force, damage)`, `SetDebrisBudget` (default 300 loose pieces, the oldest go first), events `onDestructibleBroken` / `onDestructibleDamaged`, the actor callback `onBreak(info)`. Cloth: the Cloth component (grid flag, soft ball, model section) or `CreateCloth`, `SetClothPinned`, `SetClothWind`, `PushCloth`, `SetClothPressure`; the wind follows the world wind (`weather` / `SetWind`). Limits from the engine docs: CPU cloth only (a few thousand vertices each), convex-hull Voronoi pieces, no skinned destructibles, no networking of the pieces (each machine breaks the object from the same blow: keep the damage authoritative). Debris falls through a level with no collider under it (`z` kept dropping in the test project): put the crate on a floor. Damage reply `ok:false` only means "this blow did not break it". Test in Play with `ncli destruction state` plus a GDS test that asserts health and `IsDestructibleBroken`.
- **Animation extras in the natives** (registry names only, not tried here; read `natives_search <name>` before use): montages `DefineMontage`, `PlayMontage`, `StopMontage`, `JumpToMontageSection`, `SetMontageRate`, `SetAnimationSlotWeight`; foot / hand IK `EnableFootIK`, `SetEntityIKGoal`, `SetEntityIKGoalToSocket`; sockets `AddBoneSocket`, `AttachEntityToSocket`, `GetEntitySocketCoords`; `RetargetAnimations`. The MCP `animation_state` tool grew `bone`, `bone2`, `map`, `pelvis`, `position`, `section`, `slot`, `source` for them.
